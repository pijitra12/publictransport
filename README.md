# ตัวอย่าง: วางแผนเดินทางรถไฟฟ้า + รถเมล์ (Weighted Graph + Tree)

เว็บสาธิต 3 หน้า (HTML/CSS/JavaScript ล้วน ไม่มี framework, deploy ขึ้น GitHub Pages ได้ทันที)
ทำหน้าตาและขั้นตอนแบบแอปวางแผนเดินทางที่ใช้งานจริง (ประเภทเดียวกับ Google Maps Directions /
Moovit / ViaBus): **ค้นหาเส้นทาง → เปรียบเทียบเส้นทางที่แนะนำ → ดูขั้นตอนทีละช่วงและซื้อตั๋ว**

> ข้อมูลเส้นทาง เวลา และค่าโดยสารทั้งหมดเป็น **ระบบขนส่งจำลองเพื่อการสาธิต** ไม่ใช่ข้อมูลจริง
> ของ BTS/MRT/รถเมล์สายใด ๆ

## หน้าเว็บ

| ไฟล์ | ฟีเจอร์จริง | หลักการที่ทำงานอยู่เบื้องหลัง |
|---|---|---|
| `index.html` | ค้นหาเส้นทาง (เลือกต้นทาง/ปลายทาง) | **Tree** 4 ระดับ: ทุกระบบขนส่ง → ประเภท (รถไฟฟ้า/รถเมล์) → สาย → สถานี/ป้าย (Leaf) ตัวเลือกสถานีเป็นหน้าต่างเลือกแบบ drill-down จริง — หน้าแรกมีฮีโร่แบนเนอร์ ปุ่มกรองประเภทพาหนะ (เชื่อมกับ Tree จริง ไม่ใช่แค่ตกแต่ง) และการ์ดเส้นทางยอดนิยมที่ดึงเวลา/ราคาจริงจาก Dijkstra มาแสดง |
| `results.html` | แสดงเส้นทางที่แนะนำแบบเต็ม พร้อมแผนที่และไทม์ไลน์ | **Weighted Graph** ของสถานี+สาย (state graph) รัน **Dijkstra** 3 รอบด้วยน้ำหนักต่างกัน (เวลาล้วน/ค่าโดยสารล้วน/ผสม) เส้นทางที่ดีที่สุดจะขยายแสดงเต็ม (แผนที่ใหญ่พร้อมเข็มทิศ/ซูม/legend + ไทม์ไลน์เวลานาฬิกาจริง) เส้นทางอื่นแสดงเป็นรายการย่อด้านล่าง กดสลับดูได้ มีปุ่มบันทึกเส้นทาง (localStorage) และแชร์ลิงก์ |
| `ticket.html` | รายละเอียดการเดินทางทีละขั้น + ซื้อตั๋ว | แปลผลเส้นทางจาก Dijkstra ให้เป็นขั้นตอนอ่านง่าย พร้อมผังเส้นทางขนาดใหญ่ (มีเข็มทิศ/ซูม/legend) ป้ายชานชาลาต่อสาย ตารางค่าโดยสาร และตั๋วตัวอย่าง (QR ตัวอย่าง ไม่ใช่ตั๋วจริง) |
| `favorites.html` | เส้นทางโปรด — บันทึก/ตั้งชื่อ/เรียงลำดับ/ค้นหา | อ่านรายการจาก `saved-routes.js` (localStorage) แล้วคำนวณเวลา/ราคา/จำนวนเปลี่ยนสายของแต่ละเส้นทางสดใหม่ทุกครั้งด้วย Dijkstra ตัวเดียวกับหน้าอื่น ไม่ใช่ค่าที่จำไว้ตายตัว มีตัวนับจำนวนครั้งที่ค้นหาจริงไว้เรียง "ใช้บ่อยที่สุด" |

## ผังเส้นทาง (สถานี-กราฟ)

`station-map.js` วาดผังทั้งระบบแบบ schematic (ไม่ใช่พิกัดภูมิศาสตร์จริง) เป็นพื้นหลังจาง ๆ แล้วไฮไลต์
เฉพาะเส้นทางที่กำลังดูทับด้านบนด้วยสีของแต่ละสาย ใช้ทั้งในการ์ดเปรียบเทียบ (หน้า 2 — เวอร์ชันย่อ ไม่มีป้ายชื่อ)
และหน้ารายละเอียด (หน้า 3 — เวอร์ชันใหญ่ มีชื่อสถานีครบ) เพื่อให้เห็นภาพว่าเส้นทางที่เลือกอยู่ตรงไหนของทั้งระบบจริง

## จุดที่ทำให้เป็น Weighted Graph ที่ถูกต้องจริง ๆ (ไม่ใช่แค่กราฟธรรมดา)

สถานีหนึ่งอาจอยู่ได้หลายสาย (เช่น "สยาม" อยู่ทั้งสายสุขุมวิท สายสีลม และรถเมล์สาย 511) ถ้าใช้กราฟสถานี
ตรง ๆ จะคิดเวลาเปลี่ยนสายไม่ถูก ไฟล์ `transit-data.js` เลยสร้างกราฟที่ vertex คือ **(สถานี, สาย)** แทน
("state") แล้วเพิ่มเส้นเชื่อมพิเศษ "เปลี่ยนสาย" ระหว่าง state ที่สถานีเดียวกัน ทำให้ Dijkstra คิดค่าใช้จ่าย
เวลาเปลี่ยนสายได้ถูกต้องจริง — เป็นวิธีมาตรฐานที่ระบบนำทางขนส่งจริงใช้กัน

น้ำหนักตั้งใจให้ **รถไฟฟ้าเร็วแต่แพงกว่า** และ **รถเมล์ช้าแต่ถูกกว่า** เพื่อให้เห็น trade-off จริงระหว่าง
โหมด "เร็วที่สุด" กับ "ประหยัดที่สุด" ได้ชัดเจน (ลองค้นหา "อนุสาวรีย์ชัยสมรภูมิ → สยาม" จะเห็นความต่างชัดที่สุด)

## ไฟล์ข้อมูล

- `transit-data.js` — สาย/สถานี, state graph ถ่วงน้ำหนัก, ฟังก์ชัน Dijkstra (`findBestRoute`)
- `station-tree.js` — Tree ของสถานีสำหรับหน้าต่างเลือกต้นทาง/ปลายทาง
- `station-map.js` — วาดผังเส้นทางทั้งระบบ + ไฮไลต์เส้นทางที่เลือก (ใช้ในหน้า 2 และ 3)
- `icons.js` — ไอคอน SVG วาดเอง (รถไฟ รถเมล์ เดิน หมุด ตั๋ว QR ตัวอย่าง)
- `saved-routes.js` — ข้อมูลเส้นทางโปรด + ตัวนับจำนวนครั้งที่ค้นหา (localStorage) ใช้ร่วมกันหน้า 2, 3, เส้นทางโปรด
- `save-modal.js` — หน้าต่างตั้งชื่อ/เลือกไอคอนตอนบันทึกเส้นทางโปรด ใช้ร่วมกันหลายหน้า
- `images/logo.png` — โลโก้เว็บ (ไฟล์ภาพจริง ใช้ `<img>` แทนการวาด SVG เพราะเป็นภาพราสเตอร์ที่ผู้ใช้ให้มา)

## รันดูเอง

เปิด `index.html` ตรง ๆ ในเบราว์เซอร์ได้เลย หรือรันเซิร์ฟเวอร์เล็ก ๆ:

```bash
python3 -m http.server 8000
```

แล้วเข้า `http://localhost:8000/index.html`

## Deploy ขึ้น GitHub Pages

1. สร้าง repo ใหม่ แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ไว้ที่ root ของ repo
2. Settings → Pages → Branch เลือก `main` / โฟลเดอร์ `/(root)`
3. รอสักครู่แล้วเปิดลิงก์ `https://<username>.github.io/<repo>/`
